# Handoff to EE52043: resistor values in the robot's cycle (2026-11-11)

From robot_offline's band-reading session to the EE52043 session. robot_offline can now read a resistor's
value from its colour bands. EE52043's cycle doesn't use it yet. This note says what exists, how to call
it from EE52043, and what to watch for. The changes in EE52043 are EE52043's to make. robot_offline owns
the reader, plate search and segmentation: use them through their API, don't copy them.

## The reader

| | |
|---|---|
| Model | `models/band_reader_kit_v1` (robot_offline; its README has the details). Reads each column along the body. Trained on the 31 values collected from the user's MIUZEI kit (blue 1% 5-band parts, 0R to 1M); decodes only the kit's 52 values |
| Speed | about 5 ms a body on the CPU, plus cutting the crop |
| Limit | **0.7, provisional.** `configs/band_reader.toml [deploy] min_confidence`, set by the user for live tests before an ohmmeter backup exists. The model's own limit is 0.998: delete the `[deploy]` line to go back to it |
| On held-out placements (new captures of trained values) | best guess right 97.5%. **At 0.7:** 97% answered, about **1.2% of bodies wrong** (1 in 80). At 0.998: about 51% answered, none wrong |
| How it goes wrong | a factor of ten: brown against black multiplier on a blue body (1k read as 680R, 1k5 as 150R, 5k1 as 510R) |

## The call

```python
from robot_offline.post.bands import learned, values

net = values.load()                                     # once; models/band_reader_kit_v1, CPU
readings = values.read_frame(net, frame, cal, polygons) # polygons: rectified px, from tiling.predict_frame
for r in readings:
    r.value       # ohms if confidence >= the limit, else None
    r.best        # the most likely value either way (a guess when value is None)
    r.confidence  # its share of all the kit's values
    r.colours     # the bands read, in reading order
values.in_sorter_range(r.value)   # the sorter sorts 10 ohm to 10 kohm (robot_offline docs/classification.md)
```

`read_frame` does what `tools/read_plate.py` does: white balance from the plate, each body's 20 px/mm
band crop cut from the **raw** frame, read. Checked on a real capture (`kit_one_05`, through seg_grey_v2
and read_frame): a 1k5 read as 1k5 at 0.755.

## Suggested change in EE52043 (yours to decide)

1. **`robot_control/vision/detector.py`:**
   - Load the reader once in `Detector.__init__` (`values.load()`).
   - In `detect`, after `tiling.predict_frame`, call `values.read_frame(net, frame, cal, polygons)` on the
     same rectified polygons, and pass the readings to `to_detections`.
2. **`robot_control/world/types.py` `Detection`:** add the reading:
   - `value_ohm` (None when unsure);
   - `best_ohm`;
   - `value_confidence`;
   - `bands`.
   Keep `from_outlines` working without them for the twin and the tests.
3. **Exposure:** the bands read best with the plate at grey 205–225 (`learned.READING_LEVEL`). Where
   live_plan's `Frames` builds its `plate_search.Tracker`, pass `level=learned.READING_LEVEL`, as
   robot_offline's live_detect does with values on. Segmentation is fine at that level.
4. **Sorting (`bins_real.toml`, the plan):**
   - a value in range goes to its bin;
   - `value is None` means unsure. With no ohmmeter yet, set it aside (a "measure later" bin, or leave it
     on the plate), never a value bin;
   - a value outside 10R–10k goes to the reject bin.
5. **Optional, later: close-ups** (`robot_offline.post.bands.closeup.take`), while the arm is parked. One
   capture per body at the focus its distance needs, about 1.5 s a body. On the live test the close-up
   lifted 2 of 10 parts over the limit. Average its reading with the main one as `learned.Views.pin`
   does (live_detect's `u` key).

Viewing the readings on the rig without EE52043 changes: run robot_offline's
`python -m robot_offline.inf.live_detect --last-fit`. It shows a green value, amber "measure" or grey
"not a resistor" on each body, and a readings panel. It can't share the camera with EE52043's scripts.

## Watch for

- **About 1 body in 80 gets a wrong value at 0.7,** nearly always ×10 or ÷10. With no ohmmeter there's
  no catching it. Note which bins had which parts if the tests matter.
- **Only the kit's parts.** A non-blue or non-kit resistor can be read confidently and wrongly: a
  light-green part was read as 330k at 0.96. The resistor tag doesn't screen it, because it is a resistor.
- **14 kit values were never in training:** 15k, 22k, 33k (the card's "23k"), 47k, 68k, 75k, 150k, 220k,
  330k, 470k, 680k, 2M, 4M7 and 5M6. They decode, but expect roughly 53–64% right on them (what the same
  method got on values it never saw).
- **Segmentation misses about 1 body in 10 per frame on the kit's small blue parts,** mostly on the
  near side, from blur; see `2026-11-10_segmentation_kit_findings.md`. A missed body gets no reading;
  it's still on the plate next cycle.
- **Plate finding** can stall at start-up when a lead lies over the centre cross in dim light. Keep the
  cross clear until the plate is found.
